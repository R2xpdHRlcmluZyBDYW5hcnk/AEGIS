# 历史事件与原始证据

独立服务部署的“清空历史事件”由规则管理器排他调度。规则更新、配置应用和清空任务互斥。任务状态通过运行状态快照读取，不占用事件查询队列。

清空顺序为停止日志轮转和网络范围定时器，正常停止检测引擎、事件桥接和 Web 进程，删除事件库及派生统计库、Snort 原始事件日志及轮转文件、控制台 JSON 事件流和桥接检查点，然后启动检测与采集。正常停止会关闭 NFQUEUE 监听并撤销队列规则；不使用会留下监听器的 SIGSTOP。

数据库容量设置、认证、规则、规则源授权及设备配置保留。清空无法撤销，Web 重启后可能需要重新登录。运行结果保存在管理器状态目录的 `history-reset.json`。失败会记录阶段和错误，并尝试恢复服务；已经删除的历史无法回滚。

事件查询缓存包含数据库世代和响应修订号。清空前已开始的查询也必须检查世代，不得在清空后返回旧安全事件。威胁狩猎只读 SQL 查询不获取采集器的事件缓冲锁。

安全事件包括普通告警与有签名的阻断告警。Snort reject/block 原生 notice 被归类为 drop 时仍进入安全事件分组及告警证据；没有检测签名的普通引擎丢包不单独创建安全事件。同一会话的 alert/drop 镜像按原生事件字段去重，分组仍仅依据 session_id。

安全概览将普通 alert 和带 SID 的 drop 计入检测告警，高危告警使用同一检测集合中的一级告警。阻断事件包括 drop 及动作已标记 blocked 的告警。同一条记录可同时属于检测和阻断，两者不可相加当作事件总数；趋势采用相同口径。原始日志类型保持不变，精确镜像仍优先保留 alert，独立告警不合并。

概览数值卡、排行图和趋势柱点击筛选当前概览。筛选条件与时间范围共同作用于安全计数、趋势、排行、最新安全记录和网络统计；引擎资源及累计引擎计数继续反映运行状态。条件可逐项移除或全部清除，同一维度替换原值，不同维度取交集。趋势柱选择对应的时间桶和检测类别，切换时间范围会移除时间桶。图表切换成表格后的文字行仍进入原来的日志查询，最新记录仍打开详情。

网络统计的筛选采用独立缓存键，继续由单个有界后台工作线程查询只读连接；过滤条件不会使用未过滤的预聚合结果。请求不等待计算完成，不显示其他条件的旧结果。开发电脑可使用 `python -B tests/check_overview_events.py <系统临时目录中的事件流副本>` 校验最近 15 分钟的检测和趋势计数；工具报告副本实际覆盖范围，不输出地址及原始载荷。

`level:*` 查询有签名的告警及阻断事件，也包含未评级签名；`level:unknown` 专门筛选未评级记录。没有告警级别的 DNS、连接等协议日志不命中。缺失级别不能自行补为高、中、低危。

采集桥接进程在写入事件流前从本地活动规则提取 priority、classtype 与分类默认级别，写入独立的 rule_metadata 字段，原生 data 保持不变。隔离 Web 进程读取该随事件保存的元数据，无需访问规则目录。已存历史记录缺失的元数据不使用后来规则追溯猜补。

证据抽屉格式化原始 JSON 时只调整字符串外的空白，保留整数、浮点数字面量及字符串转义；复制内容和显示内容一致，避免 JavaScript 数值解析改变原生 64 位 UID。
