# 历史事件与原始证据

## 写入与检查点

事件库保持 `synchronous=FULL`，自动 WAL 检查点阈值为 4096 页，默认 4 KiB 页对应约 16 MiB；自动检查点仍为 PASSIVE。这样可合并更多批次中的重复索引页回写，代价是检查点之间的 WAL 较大。64 MiB 日志保留上限继续生效；长读事务可能暂时阻止检查点完成，因此不是 WAL 文件的硬上限。事件记录与读取位置仍在同一事务内提交。

核查：2026-11-07，Australia/Perth，直接读取 [SQLite 官方 WAL 文档](https://www.sqlite.org/wal.html#performance_considerations)，核对默认 1000 页阈值、FULL 同步、PASSIVE 检查点及读写取舍。本地复制事件流的对照回放包含最终检查点，并比较完整行；开发电脑计时不能等同于部署设备吞吐量。可用 `python -B tests/benchmark_ingest_wal.py <系统临时目录中的事件流副本>` 复现。

## 只清空事件库

维护请求 history-reset 可指定 scope=database，HTTP 接口为 `POST /api/db/clear`，请求体 `{"scope":"database"}`。该模式只暂停控制台，将事件库、WAL、SHM 和派生统计库整体移入受保护备份，创建带新世代及事件流读取位置的空库后恢复控制台。检测引擎、原始日志、桥接采集持续运行，历史 JSON 不重新入库；认证、规则、配置、资产和容量设置保留。

旧表的时间戳 / SID / 五元组 UNIQUE 约束不在普通启动时重建。切换空库后采用新表结构，仅用来源记录 event_key 幂等去重，保留不同会话、生成器或包中时间和规则相同的证据。

## 完整历史清理

独立服务部署的“清空历史事件”由规则管理器排他调度。规则更新、配置应用和清空任务互斥。任务状态通过运行状态快照读取，不占用事件查询队列。

清空顺序为暂停日志轮转和网络范围定时器，仅停止事件桥接、Web 进程及已启用的 QUIC 观察组件。Snort 进程、包处理、规则、会话和 NFQUEUE 持续运行。旧原始日志及事件流先在同一日志分区内重命名隔离，保持已打开的文件仍可安全写入；随后调用 `reopen_logs()`，等待所有检测工作线程刷新旧缓冲并重开新文件。核对检测进程身份和旧文件句柄后，切换空事件库及新世代，重置桥接检查点并恢复采集。新日志与事件库健康检查通过后，才删除本次隔离的历史和旧事件库。

数据库容量设置、认证、规则、规则源授权及设备配置保留。清空无法撤销，Web 重启后可能需要重新登录。运行结果保存在管理器状态目录的 `history-reset.json`。失败会记录阶段和错误，并使用独立恢复上下文重新启动已暂停的采集服务及定时器。未提交删除的日志隔离目录和事件库备份会保留，其位置记录在任务状态中，可供管理员恢复；失败后已经切换到新文件的采集继续写入新日志。最终删除过程中发生的部分删除无法回滚。

启用了 QUIC 观察组件时，完整清理也会停止该组件，清理其日志后恢复。省略 scope 的已有界面操作仍执行完整清理；不要与保留原始日志的数据库切换混淆。

无中断完整清理需要引擎补丁 `ndr-session-3`。旧引擎缺少日志重开命令时，任务在停止服务和修改历史之前拒绝执行，不回退为停止 Snort。安装新引擎需要一次正常引擎更新，之后的历史清空不再重启检测进程。Python 维护入口转交给 Go 事务，避免从旧入口误用停止检测的流程。

事件查询缓存包含数据库世代和响应修订号。清空前已开始的查询也必须检查世代，不得在清空后返回旧安全事件。威胁狩猎只读 SQL 查询不获取采集器的事件缓冲锁。

安全事件包括普通告警与有签名的阻断告警。Snort reject/block 原生 notice 被归类为 drop 时仍进入安全事件分组及告警证据；没有检测签名的普通引擎丢包不单独创建安全事件。同一会话的 alert/drop 镜像按原生事件字段去重，分组仍仅依据 session_id。

启用告警抑制后，Snort 对仍然触发实际内联阻断的会话保留带签名的 drop。带 `alert_suppressed` 的记录进入阻断日志和会话网络证据，安全事件分组、告警证据、原始告警导出和概览告警统计均排除这类记录。

安全概览将普通 alert 和未抑制的带 SID 的 drop 计入检测告警，高危告警使用同一检测集合中的一级告警。阻断事件包括 drop 及动作已标记 blocked 的告警。同一条记录可同时属于检测和阻断，两者不可相加当作事件总数；趋势采用相同口径。原始日志类型保持不变，精确镜像仍优先保留 alert，独立告警不合并。

检测告警、高危告警、趋势的告警曲线和高频检测签名排行共用同一检测条件，对 alert 与带 SID 的 drop 都排除抑制标记；标记为 0 的记录按未抑制处理，缺失标记沿用历史记录口径。原生布尔值与数值抑制标记在入库时统一规范化。阻断卡片、阻断曲线、阻断日志、最近原始日志及网络可见性仍保留真实阻断与流量证据，不因告警抑制而隐藏。

概览数值卡、排行图和趋势柱点击筛选当前概览。筛选条件与时间范围共同作用于安全计数、趋势、排行、最新安全记录和网络统计；引擎资源及累计引擎计数继续反映运行状态。条件可逐项移除或全部清除，同一维度替换原值，不同维度取交集。趋势柱选择对应的时间桶和检测类别，切换时间范围会移除时间桶。图表切换成表格后的文字行仍进入原来的日志查询，最新记录仍打开详情。

网络统计的筛选采用独立缓存键，继续由单个有界后台工作线程查询只读连接；过滤条件不会使用未过滤的预聚合结果。请求不等待计算完成，不显示其他条件的旧结果。开发电脑可使用 `python -B tests/check_overview_events.py <系统临时目录中的事件流副本>` 校验最近 15 分钟的检测和趋势计数；工具报告副本实际覆盖范围，不输出地址及原始载荷。

`level:*` 查询有签名的告警及阻断事件，也包含未评级签名；`level:unknown` 专门筛选未评级记录。没有告警级别的 DNS、连接等协议日志不命中。缺失级别不能自行补为高、中、低危。

采集桥接进程在写入事件流前从本地活动规则提取 priority、classtype 与分类默认级别，写入独立的 rule_metadata 字段，原生 data 保持不变。隔离 Web 进程读取该随事件保存的元数据，无需访问规则目录。已存历史记录缺失的元数据不使用后来规则追溯猜补。

证据抽屉格式化原始 JSON 时只调整字符串外的空白，保留整数、浮点数字面量及字符串转义；复制内容和显示内容一致，避免 JavaScript 数值解析改变原生 64 位 UID。
