# 本地模型研判

事件证据提供按需总结。安全事件研判每次打开自动生成总结；规则建议需要点击“生成规则建议”。总结和建议只在当前详情中显示，不写入事件库。规则建议在服务端内存保留最多十分钟、最多十六条，并绑定登录会话；只有“添加并应用规则”会提交变更。

## 接口与资源

Web 后端以流式 HTTP 连接本机 `127.0.0.1:18080/v1/chat/completions`，模型为 `Qwen3.5-2B`，关闭思考。会话总结最多两次顺序推理：狩猎计划最多 64 token，最终分析最多 384 token；整个请求共用 180 秒期限与单个推理槽位。没有会话 ID 时只做一次单条事件总结。适配同机单并发、2048 上下文、无状态部署，不新增依赖或模型代理。`ips-web.conf` 的 `local_llm.enabled=false` 可关闭功能，生产配置和认证保留在源码仓库外。

`POST /api/ai/generate` 接收 summary / rule 和事件查询标识，后端重新读取事件，禁止客户端传任意提示词或证据。响应为逐行 JSON。只有一个推理槽位，不排队；证据查询仍经过已有有界查询调度，模型等待不占用规则修改锁或查询工作线程。对模型只发送字段白名单中的摘要、通信地址、签名和有限网络样本，不发送原始载荷、认证配置或完整事件 JSON。系统提示词与输入合计限制为 1500 个 UTF-8 字节，为 384 个输出 token 和消息模板保留余量；超限时删除完整样本、候选或摘要字段，不截断 JSON 或规则条件。输入不是完整事件，提示词明确要求披露证据不足。

浏览器用 AbortController 持有流式请求，关闭详情、返回、切换详情或页面、卸载页面时取消。切换浏览器标签页或浏览器失去焦点时继续生成。后端在等待模型期间每 0.2 秒检查客户端连接，断开后关闭上游流式套接字，触发模型服务的原生断线取消。不会调用影响其他客户端的全局 `/v1/abort`。取消时丢弃输出，不创建规则。网络中断的发现依赖 TCP / 代理断线传播；不能承诺操作系统或 NPU 在绝对零延迟内停止。反向代理须保留流式响应及断线传播，响应带 `X-Accel-Buffering: no`。

## 提示词与规则边界

提示词在 `llm_assistant.py` 维护。SUMMARY_PROMPT 用于两处总结，允许分析正常通信、可疑活动和威胁事件，不强制把会话归类为攻击。输出通信概览、行为与处置、研判依据、建议核查；要求区分事实、推断和证据缺口，不把告警等同于入侵成功。HUNT_PROMPT 教模型使用当前面板的真实搜索语法。RULE_PROMPT 提供精简 Snort 3 编写知识，说明规则头、HTTP Host 缓冲区、flow 条件、SID 和 rev，并要求模型返回候选编号、描述、选择依据和误报限制。

## 会话证据与狩猎

后端根据事件的真实 `session_id` 使用已有索引检索同一会话的全部已保留记录，不以源目的地址、五元组、Community ID 或原生 UID 猜测会话关联，也不局限于当前列表的时间窗口。没有引擎会话 ID 时保留为单条证据分析。查询使用既有只读快照和有界调度；不让模型直接访问数据库、文件系统、命令行或任意 SQL。

输入优先保留通信两端与协议、日志类型及处置计数、最新连接状态和双向流量、检测签名与规则身份、实际动作，以及 DNS、TLS、HTTP 等代表性记录。流量取最新连接记录的值，不对累计更新反复求和；统计值由后端计算。HTTP URL 仅保留路径，不发送查询字符串、原始报文或认证配置。最终输入优先保留命中摘录，合并重复证据，并明确为部分字段摘要。模型输入较小时会省略较低优先级细节；界面显示会话总记录数与实际证据摘录数。

后端按已检索到的会话事实准备结构化核查项：告警与处置、HTTP 错误响应、DNS 常见失败响应、已观察到的域名线索、单向连接记录。模型只选择核查项 ID，搜索词由后端生成，避免将中文说明误当作狩猎语句。告警与处置核查始终执行，再最多选择一项相关核查。返回格式错误、未知 ID 或计划截断时，执行基础核查并在界面说明回退；不把自然语言拿去执行或显示为搜索词。

后端强制加上当前会话约束，并执行与面板相同的解析和结构化筛选。每条限制 160 字、布尔深度与字段白名单，必须能完整下推为参数化 SQL；只返回命中数和最多四条字段摘录。不开放全库自主搜索、原始载荷扫描、任意 SQL 或循环追加查询。检索后刷新同会话事实，将实际命中和摘录送入最终总结。条件校验错误与执行错误分别展示，不把失败当作零命中。回退复用同一推理流程，不增加模型调用次数。

支持的示例条件：

```text
type:alert OR type:anomaly OR action:blocked
type:http AND status:>=400
type:dns AND rcode:NXDOMAIN
level:high AND action:allowed
```

异常状态或命中条件不是恶意活动的充分证据；未命中也不能证明安全。计数按入库日志记录统计，alert / drop 可能分别记录同一处理过程，不代表独立攻击次数；不同查询的命中可以重叠。界面保留实际执行的完整会话搜索词和命中数，“查看命中日志”以相同搜索词与会话时间范围打开威胁狩猎。规则生成及应用仍是独立的明确操作。

模型只能选择后端从当前证据提取的 TCP / UDP 通信端点，或同方向 HTTP Host 条件。服务器将选择渲染为受限 Snort 3 规则，拒绝模型发明的地址、端口、协议和任意规则选项。规则默认 alert，仅产生告警；端点匹配不能识别漏洞载荷，HTTP Host 使用子串匹配，可能覆盖正常访问或造成重复告警。证据不足时不生成规则。没有使用 DNS 名称直接匹配原始报文或把 TLS SNI 当作 HTTP Host。

`POST /api/ai/rules/add` 只接收本会话建议令牌，不能替换规则原文。独立规则管理器分配未与活动及待应用规则文件冲突的 SID，并启动 manual-add 事务。规则只写入 `ips-web-hunting.rules`，由现有 Snort 配置独立 include；不交给订阅规则合并器，不改写订阅规则文件，不应用其他待处理配置。Snort `-T` 验证整个活动配置后热重载，失败恢复旧文件，重载失败则尝试恢复旧规则集。成功后把已应用规则同步到待应用快照，保留其余待应用编辑。提交记录支持重启后恢复同步。重复点击同一建议返回同一任务。

规则应用是已明确确认的配置事务，开始后继续完成或回滚；关闭详情只停止模型生成。应用结果可在规则管理任务日志查看。生成建议未通过实际引擎校验前不标记为有效规则。
