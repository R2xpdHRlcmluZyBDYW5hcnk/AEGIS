# 并行处理与一致性边界

控制台、规则管理器和数据桥使用分配给控制面的 CPU。子进程继承服务的 CPU 亲和性，不改变 Snort 检测进程、队列或引擎实现。计算并行采用标准库的 spawn 进程池，不在已有多线程服务中 fork。

## 模块与任务

| 路径 | 并行方式 | 顺序边界 |
| --- | --- | --- |
| `parallel_cpu.py` | 每个服务复用最多 4 个计算进程，所有调用共享有界提交名额 | 每条流水线最多挂起与进程数相同的批次，按输入顺序返回 |
| `parallel_sql.py` | 查询线程加最多 3 个共享辅助线程，各自拥有只读连接 | 同一业务查询固定 WAL 读快照；不共享连接跨线程执行 SQL |
| 概览、事件、告警分组 | 计数、分页和独立聚合 SQL 并发执行 | 计数、排行和列表使用同一快照，原始事件类型与去重口径保持一致 |
| 网络快照刷新 | 单个独立后台读线程，聚合 SQL 在同一只读事务内顺序执行 | 不借用前台 SQL 辅助线程，筛选缓存隔离，保留刷新期限和超时 |
| 数据桥 | 完整行分块后并行解析 JSON、识别类型及编码输出 | 单写者有序提交；输出文件及目录同步完成后，原子更新并同步检查点 |
| 事件入库 | 并行规范化、计算事件摘要及压缩原文 | 解析整批成功后才更新内存与读取位置，SQLite 保留单写者 |
| 历史投影补齐 | 批量并行计算关联标识 | 派生库事务和游标提交顺序不变，后台仍按工作占空比让出资源 |
| 文本规则目录与内置目录解析 | 较大输入分块解析，复用服务计算池 | 先规范化续行，再分完整规则，保留文件、记录及重复签名顺序 |
| Python 事件适配器的规则评级元数据 | 大型评级目录分批并行解析，缓存重建互斥 | 按文件和规则顺序合并，保留优先级与最后出现的规则；不修改 Snort 引擎 |
| Python 查询条件与 ATT&CK 原文匹配 | 完整候选行批量交给计算进程 | 保留布尔条件、分页、精确整数、扫描限制和取消；原本完整下推的元数据查询仍完整检索或超时报错 |
| 原始日志与内存兼容查询 | 批量解析和过滤并行 | 保留原有条数、扫描范围、顺序与分页；日志句柄由协调线程关闭 |
| 多规则源更新 | 最多两个来源任务并发，按总进程预算限制各自解析器 | 来源结果按固定顺序合并；共享来源索引加锁，冲突失败不替换生效规则 |
| PulledPork3 | 保留现有下载、流式提取和分块多进程解析 | 上游身份、校验、重复规则优先级和补丁版本继续验证 |

目录控制、连接生命周期、单条记录的操作、SQLite 提交、检查点推进、规则冲突合并与最终文件替换是协调步骤。浏览器 DOM 更新遵循浏览器主线程约束。单条 SQLite 语句内部仍由 SQLite 执行，并行安排在独立 SQL 和候选行处理层，不能仅因线程数增加而声称一条 SQL 平均占用四核。

## 资源与调度

前台默认允许 4 个读取请求，其中概览保留一个名额，其余用于日志；预取、网络快照与历史补齐继续独立调度。SQL 辅助线程由服务共享，不随请求无限创建。当辅助线程已占用或写入锁繁忙时，当前查询仍可用独立只读连接完成，不等待写入锁。辅助连接初始化成功后才释放快照协调锁；投影提交也参与相应的协调。

实时连接在计算前和刷新等待期间检查客户端断线，关闭或快速翻页时及时释放有界连接名额；等待检查不发起额外查询。连接上限维持不变。

网络快照单次后台计算限时 60 秒。启动时预热一次默认范围，之后只刷新最近 60 秒内访问过的范围，正常每 30 秒刷新。失败以 5 秒起步退避，最长 60 秒。每次计算后的后台刷新与重试共同等待至少三倍于本次线程 CPU 时间的冷却期，持续刷新约占单核的四分之一。新访问范围的首次计算可以提前进行，仍逐个计算。会话排序只处理有身份的记录，旧版无身份连接摘要直接逐条计入。

只更新 Web 专用模块且无其他服务资源变更时，部署器仅替换变化模块并重启 ips-web；校验失败同样仅回滚控制台。未变化的配置和服务资源文件不重写，检测引擎、日志桥和规则管理器保持运行。

同一范围和筛选条件的成功网络快照在刷新失败或超过新鲜期限后仍保留，标注原更新时间及更新延迟，不以零或空图替代。缓存仍受字节预算和条目数约束；清空历史或数据库世代变化立即使旧快照失效。冷启动、缓存淘汰或新筛选条件没有成功快照时显示准备状态或真实错误，不借用其他条件的数据。

页面读取缓存按完整查询、时间参数和分页键隔离；最多保留 15 分钟的成功结果供后台刷新期间使用，超过新鲜期限或刷新失败时返回 read_state，界面显示延迟提示。后台刷新合并、队列和失败重试间隔均有界，失败结果不覆盖成功缓存。参数变更、清空历史和写操作会使相应缓存失效；入库故障仍从实时写入状态返回。初次查询的语法及数据库错误正常报告。

默认 24 小时概览、安全事件、阻断与无筛选狩猎首屏优先保留在共享响应缓存。启动时由单个后台工作线程预热，首个快照尚未就绪时合并同条件查询。成功提交新增事件后按批合并刷新，同一首屏至少间隔 15 秒，耗时查询延长冷却期。无新增事件时按数据进入或离开窗口及图表时间桶边界更新。概览的网络统计与运行状态仍使用各自的采样结果。自定义条件及后续分页按需查询。

部署时可通过 `deploy.ps1 -UpdateBackend -PreloadMemoryMiB 512` 设置缓存和近期事件缓冲合计的固定字节上限，允许 1 至 1024 MiB。显式固定值优先于旧的内存比例和上限设置，缓存按实际使用逐步占用，SQLite、工作进程及其他服务内存另计。未设置固定值的实例继续使用原有缓存预算策略。

开发机可运行 `python -B tests/benchmark_first_pages.py --baseline <提交>`，使用同一份合成数据库对照冷首屏、重复读取和持续入库下的进程 CPU 时间。该基准使用真实 HTTP 与 SSE 入口，独立引擎状态采样和网络聚合不计入其 CPU 窗口。

浏览器实时流短暂断开时立即尝试一次 REST 读取，持续断开期间定期补读；短暂恢复不显示连接失败。持续失联保留最近结果并报告，收到成功数据后恢复显示。查询替换时取消旧请求、订阅和重连提示计时器，旧响应不能覆盖新条件。

概览的地址排行按全部日志出现次数统计；连接应用、传输协议和连接源按真实会话身份去重，生命周期快照不重复累计连接或流量。DNS、TLS、事件类型和检测签名筛选扩展到具有相同引擎会话身份的日志，IP 与协议继续直接约束，独立筛选维度可以跨记录匹配同一会话。DNS 与后续 TCP 连接不因时间或地址相近而合并。没有会话身份的旧记录仅在本身为连接摘要时计入连接，保留原始日志。

派生网络投影格式为 3，补充会话身份和双向包数；升级时由原有有界后台补齐任务重建派生数据，不重写事件库。滚动时间范围在快照计算时解析，避免将每次请求的时间戳变成新的缓存键。

计算进程数由 CPU 亲和性和 `IPS_CPU_WORKERS` 限制，最多为 4。较小输入直接执行，避免进程间复制和调度开销；索引规则策略保留已有直接执行路径，大文本扫描使用有界进程。多来源更新限制嵌套的 PulledPork3 解析预算，并保留 `IPS_PULLEDPORK_WORKERS` 的更低上限。单个来源仍可使用完整解析预算。

数据桥每轮读取总量有界，各输入文件轮转调度；有余量时继续处理尚有积压的文件。记录长度、文件数量和稀疏区域恢复仍有限制。服务的 CPU 配额支持四核计算，内存上限为 256 MiB。规则管理器任务上限为 64，以容纳受限的 RPC 线程、来源任务和计算子进程。

入库发现积压后及时处理下一批；空闲和写入错误使用较低频率重试。写入失败保持待提交数据，不继续吞入新的无界积压。CPU 池发生工作进程故障后，失败的批次向调用方报错，下一次任务重新创建工作池。服务停止时取消排队任务、打断 SQL 并等待工作进程回收。

## 恢复与验证

数据桥不在空闲轮询中反复同步文件和重写检查点。磁盘写入或工作进程失败时，检查点保持在上一次已持久化的位置；重启可重放原生日志。崩溃可能留下重复的完整记录，事件库使用既有事件身份去重。输出尾部未完成的行在有界范围内截断并从源日志重放，完整原生日志保持不变。超出恢复边界时停止并保留证据。

后端部署备份并校验程序、配置及独立的并行资源覆盖文件；启动失败时回滚。资源覆盖只涉及数据桥与规则管理器，不更新检测服务。部署使用 `deploy.ps1 -UpdateBackend`，并按需要显式设置 `-WebReadWorkers 4`。

`tests/test_parallel_runtime.py`、`tests/test_bridge_recovery.py` 验证实际工作进程、并行 SQL、固定快照、取消、工作池恢复、故障重放和串行结果一致性。`tests/check_multicore.py` 仅在开发电脑临时目录生成合成数据，比较单工作单元和四工作单元的完整输出摘要及实际耗时；可用 `--html <源码外路径>` 导出包含代码和完整输出的独立报告。报告不代表路由器性能，也不承诺所有小任务提速。
