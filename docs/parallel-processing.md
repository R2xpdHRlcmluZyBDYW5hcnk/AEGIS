# 并行处理与一致性边界

## Go 控制台

`backend` 提供 Go HTTP、事件库、签名管理、事件桥接、检测守护与维护入口。每个进程在启动时依据其所属 systemd 服务的 CPU 配额、有效 cpuset 和 CPU 亲和性确定工作预算。`GOMAXPROCS`、解析池、SQL 帮助线程和任务队列随该预算分配，不再使用旧的四线程常量或 `IPS_CPU_WORKERS` 覆盖服务分配。部署保留管理员已有 CPU 配额和亲和性；新安装仍可使用默认四核预算。Snort 工作线程及 NFQUEUE 数只依据承载检测引擎的服务，而非 Web 服务。完整口径见 [Go 运行服务](go-runtime.md)。

入库采用单写者与 WAL；只有事件事务提交成功后才发布读取游标。桥接将完整行分成有界批次，并行解析后按来源顺序写出，文件及目录同步完成后提交检查点。独立 SQL 使用共享上限为服务工作预算减一的辅助连接，协调写入锁固定同一个读快照；前台请求名额随服务工作预算分配，概览保留一个名额。未取得辅助名额时使用自己的只读连接，不再创建线程池。

网络统计使用单独后台读取通道，最近事件使用有容量上限的内存 SQLite。成功的网络结果受总字节预算与 32 个条目限制，刷新失败保留原结果；无成功结果时显示准备状态。原始文件补查有单独名额，最多扫描末尾 200 MiB；两遍有界扫描得到精确总数和分页，避免内存随分页偏移增长。前台切换条件或断开连接会取消对应计算。SSE 在长查询期间发送心跳，不用固定的连接时限反复中断查询。

默认概览在服务启动后主动预热聚合快照。已有结果直接从有界 JSON 快照缓存返回，绕过查询名额及内存事件池锁；普通入库只触发合并后台刷新，不清除可用结果。只有首次生成、条件首次访问或历史世代变化时等待匹配的结果，等待可由客户端取消，后台共享任务继续完成。常驻池每批优先合并新提交事件，再用剩余预算预热历史，历史预热不阻止实时追赶。桥接与检测守护共用日志布局：持久布局读取日志根目录下的 `snort` 子目录，旧布局读取 `/var/log/snort`；来源目录不存在时启动失败，不发布空闲成功状态。

内存事件库由一个独立存活连接持有，另外最多一个连接用于串行刷新和查询。取消请求后，查询连接可以被连接池丢弃与替换，表结构和已有记录不会随它销毁；新连接重新设置内存临时存储和查询函数。来源暂时读取失败时保留可用快照并标记更新延迟，恢复后清除提示；仅内存缓存损坏或缺失时自动重建并从持久事件库重新预热。健康接口记录缓存重建次数及不含查询内容的 SQLite 错误码，磁盘数据库和历史游标不受重建影响。生命周期回归覆盖反复取消查询、缓存表结构缺失、来源故障恢复和容量回收。

历史入库每次事务最多处理 1000 行。积压超过 8 MiB 时，每轮先处理事件流末尾最多 256 KiB 的完整记录，再推进历史批次；前者只写事件，不推进持久历史游标。历史仍逐行补齐，交叠记录通过原有事件摘要去重，重启可安全重放。健康接口分别报告历史与最近事件的字节积压，以及常驻池实际时间范围；读取或规范化失败会反映为入库错误。

签名来源并发数取已选来源数与服务工作预算的最小值，Go 策略解析复用有界工作池。候选生成与目录解析可并行；配置锁、签名冲突合并、校验、热重载、检查点和最终替换保持有序。签名事务持有跨进程配置锁直至提交或回滚结束，失败时保留未应用编辑。状态发布独立于引擎采样和签名操作，不要求 HTTP 请求打开引擎套接字。

Go 兼容性测试覆盖精确大整数、字段查询、MITRE 原文匹配、网络统计与安全事件分组；生命周期测试覆盖登录与来源校验、批量编辑回滚、失败配置校验、UTF-8 日志分页及稀疏日志恢复。运行 `python -B build_tools/go_backend.py -- test -race -count=1 ./...` 验证竞态。旧 Python 实现已删除，合成兼容样例保留在 backend/internal/console/testdata。

## 顺序与资源边界

| 路径 | 并行方式 | 顺序边界 |
| --- | --- | --- |
| JSON、事件规范化与查询候选 | 复用服务工作池，排队容量为工作数两倍 | 按输入次序返回，失败取消剩余工作 |
| 独立聚合 SQL | 当前查询及有界辅助连接 | 同一业务查询固定读快照，不跨线程共享连接 |
| 网络快照 | 独立后台调度，队列按预算分配 | 不借用前台名额，筛选缓存隔离，失败保留成功快照 |
| 事件桥接 | 完整行有界批次并行解析 | 输出及目录同步后再提交检查点 |
| 事件入库 | 并行规范化及摘要 | SQLite 单写者，事务提交后发布读取游标 |
| 签名更新 | 有界来源并发与共享解析池 | 固定顺序合并，配置锁覆盖校验、切换、重载及回滚 |
| QUIC | 有界字段解析与重排缓冲 | 会话状态按抓包原顺序更新，输出失败取消解码 |
| Snort | 按检测服务自身 CPU 预算确定线程及 NFQUEUE 数 | 配置与队列拓扑在启动时确定 |

单条 SQLite 语句仍由 SQLite 执行，不能仅因增加线程数而声称单条 SQL 可平均占用所有核心。模型推理、配置事务与数据库写入按一致性要求串行。

桌面浏览器验证使用 `python -B tests/run_browser_regression.py --release <发布包>`，运行真实 Go HTTP 入口及合成夹具。部署回滚使用 `python -B tests/run_backend.py`。全部数据回放、性能测试和索引测试在开发电脑临时目录执行，检测设备只接受必要部署和轻量健康检查。

## 概览快照与统计并行

概览按完整筛选、时间范围及视图参数隔离缓存。统计卡片、趋势、排行和最新日志由同一份冻结数据生成，作为整体发布。切换筛选时，最新日志先进入已有的表格加载状态，不继续显示旧条件的行；清除筛选恢复对应快照。

快照调度器只运行一个后台聚合任务，同一条件请求合并，待处理集合最多为服务工作数的八倍，已完成 JSON 总预算为事件池预算的八分之一。成功结果不因普通入库过期删除；活跃条件按源版本刷新，同一条件至少间隔 2 秒，并在该条件再次刷新前等待至少三倍本次耗时。空闲筛选暂停刷新，默认概览持续预热；失败至少等待 5 秒后重试，已有结果保留并标记延迟。清空历史或显式失效会撤销旧世代结果，并拒绝迟到任务覆盖新数据。

生产统计镜像位于 systemd 管理的 /run/ips-web-overview 私有 tmpfs 目录，权限 0700。SQLite Backup 在短暂持有内存池锁时复制已驻留的页，不读取持久数据库建立镜像；完成后镜像改为只读。镜像容量不超过事件池预算，同一版本复用一份镜像，不随工作线程数复制多份完整数据库。独立私有缓存的只读连接随后动态分配独立 SQL，最多使用服务 CPU 预算对应的读取数；新事件可在统计期间继续合并到内存池。只读连接全部释放后回收旧镜像，服务停止时释放缓存，异常退出由 RuntimeDirectory 生命周期清理。

SQLite 共享缓存连接仍可能串行化聚合，因此不能只靠增加该内存库的连接数实现并行。冻结镜像使用独立私有缓存连接，保持同一数据版本；回归通过同时阻塞多个 SQL 探针验证实际并发，并核对入库期间的计数、结果次序、只读限制和镜像回收。单条 SQL 仍由 SQLite 执行，不能据此声称单条 SQL 会平均使用全部核心。
