# 规则目录与页面查询

规则页面通过 `/api/rules/page` 一次读取当前标签的数据、待应用状态和引擎状态。签名目录、规则分组和规则源不额外生成治理列表；治理标签只读取一次治理数据。定时更新状态随规则源页面返回。运行规则任务时暂停规则页的周期性整页刷新，任务状态继续独立轮询，完成后再刷新目录。

规则原文解析由 `rule_inventory.py` 管理，活动文件、上游归档及待应用视图共享同一份只读解析结果。LRU 缓存最多保留 32 个文件，记录对象与字符串预算为 128 MiB；文件 inode、修改时间或大小变化时重新解析。超出预算的输入仍能读取，不长期占用缓存。

目录成员、编译动作、来源开关和内置规则状态独立派生。修改禁用策略不会因此重新解压不变的归档。同一次只读请求固定目录快照，辅助函数复用已检查的目录；下一次请求重新检查文件元数据，发现新增文件或来源变化。来源加组名的选择器不变。

签名浏览顺序在目录变化时计算，普通翻页复用该顺序。来源可见性集合也在目录重建时计算。空的策略排除集合直接通过，不对每条签名反复规范化相同选择器。

未带搜索条件或策略排除的签名翻页直接复用目录对应的可见顺序，不在每次请求中遍历完整签名集合。目录文件、来源或策略变化时，该顺序与索引一起失效。分组详情先过滤成员、截取页码，再生成响应对象；同名来源的组通配选择先去重。规则解析先定位选项名称，正则仍校验完整边界；消息按连续未转义文本解析，保留转义字符。归档按顺序读取，成员流使用后立即关闭。

规则页切换标签、替换查询或关闭时取消旧 HTTP 请求。页面只保留当前页及跨页选中的规则信息，已浏览但未选中的原文及时释放。面板、日志及系统页共用的实时查询也会取消旧请求，并限制同一订阅的 REST 回退请求至一个；收到 SSE 帧后取消冗余回退，避免旧响应覆盖新数据。


Community 官方归档只提供 `snort3-community-rules/snort3-community.rules`，因此保留 `snort3-community` 单一分组。来源停用时，规则分组和检测签名页隐藏只属于该来源的规则；独立手动规则以及仍被其他启用来源提供的签名保留。

“应用更改”始终离线执行来源启停、禁用、动作和告警抑制策略，不下载规则。已验证归档的 PulledPork3 基础候选和分组映射保存在缓存的 `derived` 子目录；归档 SHA-256、候选 SHA-256、上游策略、快照及解析器版本匹配时直接处理本地策略。旧缓存首次使用时离线重新解析；没有归档时提示先更新，不退回在线模式。

“更新规则集”每次都重新下载官方归档和校验文件，或重新请求自定义源；没有 TTL、条件请求或内容未变时跳过网络的路径。存在待应用来源配置时，手动更新下载草稿选中的来源而不改变引擎，之后由“应用更改”启用。没有来源改动时，在线更新继续校验并热重载当前来源；定时更新始终使用生效配置。




阻断动作批量切换和规则源启停在成功后移除已处理的选择；部分失败只保留失败条目。选择器弹窗向父列表报告实际完成的选择器，全部失败时保留原选择，便于重试。


验证时将所需规则文件及归档复制到开发电脑临时目录，在本地比较冷加载、缓存加载及策略文件变化后的查询，不在检测设备上压测。回归覆盖缓存容量与失效、策略编辑后的新状态、请求内快照、新文件发现、来源隔离和 Community 单组结构；浏览器回归检查加载、切换标签、保存及刷新只发出一份页面查询。
